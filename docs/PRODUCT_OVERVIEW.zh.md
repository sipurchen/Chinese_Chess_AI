## 一、願景

以有依有據的象棋理論為核心，建立一個 Web 中國象棋 AI 平台。有別於不透明的神經網路引擎，本系統透過具名理論框架公開推理過程——讓玩家清楚看到「為何選擇此步」。

第二階段目標是打造沉浸式**武俠仙人對弈**美術風格，將引擎包裝成紙娃娃角色系統、漸進難度解鎖，並結合多 AI 協作（Claude + Gemini + ChatGPT）。

## 三、核心理論

### 3.1 擒王分數

中國象棋唯一目的就是擒獲對方將/帥。所有評估最終回答：**「幾步後能擒王？」**

```
分數 = MATE_SCORE − 擒王所需步數
```

更快的殺局必然排名更高；對方最佳應對已透過 Alpha-Beta 搜索完整納入計算。

### 3.2 子根理論

靜態交換評估（SEE）對每個可被吃的棋子進行分類：

| 分類 | 條件 | 評估調整 |
|------|------|---------|
| **無根** | 無防守；吃子獲利 | +15 |
| **虛根** | 看似有防守，但反吃仍虧子 | +5 |
| **有根** | 防守完善；吃子吃虧 | −5 |

### 3.3 解殺還殺

當己方被將軍時，在走法排序中優先考慮反將——避免被動防守，迫使對方自行解決威脅。

### 3.4 雙方先手

`_quick_mate_threat()` 比較雙方最快強殺步數。若雙方都有威脅，殺路更短的一方取得先手優勢。

## 四、功能總覽

### 4.1 核心引擎（engine.py）

| 功能 | 說明 |
|------|------|
| 規則 | 7 種棋子全規則、白臉將、蹩腿馬、炮架子、九宮限制 |
| 搜索 | Alpha-Beta + 靜止搜索 + 迭代加深 |
| 置換表 | 15 萬條目，TT_EXACT / TT_LOWER / TT_UPPER 旗標 |
| 殺手著法 | 每層 2 個殺手著法，每次搜索重置 |
| 一步殺捷徑 | O(合法著法數) 前置掃描，跳過全深度搜索 |
| 殘局模式 | `is_endgame()` — 重子 ≤ 3；棋子價值調整 |
| 開局辨識 | 偵測當頭炮 / 過宮炮 / 飛相局 |
| 中局機動性 | `(己方著法數 − 對方著法數) // 4` 加分 |

### 4.2 AI 棋手個性

| 棋手 | 風格 | 搜索深度 | 開局書 |
|------|------|---------|--------|
| 初學者 | 從前三著法中隨機選 | 1 | 無 |
| 柳大華 | 戰術型，快攻風格 | 3 | 橘中秘 + 夾炮屏風 + 反宮馬 |
| 胡榮華 | 陣地型，殘局精確 | 4 | 五六炮 + 士角炮 + 龜背炮 + 卒底炮 |

### 4.3 知識庫（ai_memory.py）

- **14 種殘局勝法**：雙俥錯殺、馬後炮、臥槽馬、海底撈月、重炮殺法…
- **10 種殘局和法**：車炮萬年和、馬炮對車、士象全守和…
- **8 套開局書**（顏色無關，黑方自動鏡像）
- **中局戰術手段** + 棋子位置評分表

### 4.4 四模式 Web UI

| 模式 | 用途 |
|------|------|
| 人機對弈 | 與 AI 對局（即時） |
| AI 對弈 | 觀看三名 AI 循環賽（100 局） |
| 分析棋局 | 載入棋譜逐步回放 + AI 分析 |
| 試解殘局 | 自由擺棋 + AI 求解 + 儲存/相似殘局推薦 |

### 4.5 輔助系統

- **賽事系統**（ai_tournament.py）：多執行緒三方循環賽，輸出 JSON 摘要
- **殘局題庫**（ai_endgame.py）：5 道內建殘局 + 使用者儲存，Sørensen-Dice 相似度搜索
- **自對弈**（self_play.py）：棋盤影像渲染（跨平台字體），轉折點自動截圖
- **棋手維基**（ai_wiki/）：柳大華 / 胡榮華 棋風分析與代表作
